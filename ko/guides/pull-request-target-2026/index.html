pull_request_target
11월 2일 이전 점검.

GitHub는 일부 적용 대상 공개 저장소에서 pull_request_target 이벤트를 차단하는 기본 정책을 2026년 11월 2일부터 적용할 예정입니다. 모든 저장소나 모든 PR 워크플로가 막히는 것은 아닙니다. 변경에 앞서 Actions 정책 인사이트에서 영향을 받는 실행을 먼저 확인하세요.

공개 YAML 1개 점검 · 4 USDC ↗GitHub 공식 안내 ↗

적용 범위를 정확히 확인하세요. 기존에 적용 가능한 Actions 이벤트 정책이 없는 공개 저장소에 기본 차단 정책이 추가됩니다. 비공개·내부 저장소에는 적용되지 않고, 이미 존재하는 적용 가능한 정책을 대체하지 않습니다. 적용 전에는 평가 모드로 영향 분석이 가능합니다. 시행 범위·일정은 GitHub 공식 문서에서 다시 확인하세요.

01 / 확인할 사항

변경 전 네 가지
실전 점검.

내 저장소가 실제로 영향을 받는지 확인하기 전에는 장애나 보안 사고가 발생했다고 단정하지 않습니다.

1 / 목록화

이벤트 설정 확인

본인 저장소의 .github/workflows/*.yml·*.yaml에서 pull_request_target 사용 여부를 찾습니다. 토큰 권한, 시크릿 사용, 환경과 외부 액션을 함께 기록하되 비밀값은 공유하지 마세요.

2 / 실제 영향

정책 Insights 확인

권한이 있는 저장소 관리자가 Actions 실행 정책의 평가·인사이트를 확인해 실제 차단 대상 실행을 파악합니다. 이미 별도 정책이 존재하는 저장소는 결과가 다를 수 있습니다.

3 / 신뢰 경계

특권과 외부 PR 코드 분리

쓰기 가능한 토큰, 비밀키, 포크 PR HEAD 체크아웃, 외부 스크립트 및 의존성 실행 여부를 확인합니다. pull_request_target는 기본 저장소의 높은 신뢰 컨텍스트에서 실행됩니다.

4 / 선택

대체하거나 제한적으로 허용

특권이 필요 없다면 최소 권한의 pull_request로 분리합니다. 이벤트가 꼭 필요하면 적용 가능한 Actions 정책에서 필요한 워크플로만 명시적으로 허용하고, 외부 PR 코드를 특권 컨텍스트에서 실행하지 마세요.

02 / 참고 설정

일반 테스트에
권한 최소화.

Node.js 프로젝트의 설명용 예시입니다. 실행 전 직접 사용하는 외부 액션과 의존성을 검토하세요.

● ● ●   .github/workflows/pr-tests.yml — 가상 예시
name: PR checks
on:
  pull_request:
permissions:
  contents: read
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - run: npm ci
      - run: npm test

기존 특권 워크플로에 그대로 붙여 넣지 마세요. 포크 PR 테스트는 실행 승인 절차가 필요하거나 시크릿 접근이 제한될 수 있습니다. 실제 운영 환경에서는 검토된 액션 전체 커밋 SHA 고정과 프로젝트별 위협 모델을 고려하고, CI를 통과시키려고 시크릿을 신뢰할 수 없는 PR 실행으로 옮기지 마세요.

체크아웃 보호도 이미 강화됐습니다. 2026년 6~7월 GitHub는 지원되는 actions/checkout 버전에서 대표적인 포크 HEAD 체크아웃 위험을 거부하도록 변경했습니다. 하지만 쉘 명령으로 받는 외부 코드, 다른 저장소, 별도의 이벤트 위험까지 전부 막는 기능은 아닙니다. 차단을 피하기 위한 무분별한 예외 설정을 권장하지 않습니다.
